# Original sealed capture in the root Label startup fixture

The runtime root Label matrix starts from the real original-inventory initializer:
capture, seal, protection, registration and complete initial audit. It verifies one
sealed capture containing the root and its original file before creating the two
born directories and the prior file move. The fixture keeps all later original
proof, interruption, new-role, full-tree, byte, deletion and live-admission checks.

The previous setup only created individual protection baselines and registrations.
It never created a sealed root capture, although current-inventory startup requires
one for a captured-original root. The original ARM64 report retained 117 passes and
one startup-admission failure. This corrects that fixture precondition rather than
relaxing the production recovery guard or its failing assertion. Further native
behavior remains subject to the source-bound CI report.

The six Active/Disabled interruption cases and each original 60-second token are
unchanged. Local checks compile and discover this matrix only. No native Cloud
Files registration, installed App or source Worker runs on the personal profile.
This fixture correction establishes no CfSharp defect or full S06 acceptance.
