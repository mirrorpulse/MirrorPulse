# Controlled protected root Label execution

The Host root Label executor consumes the original version3 protected-subtree
admission and original public SDK move proof. It verifies the physical sync-root
anchor, every sealed member, complete local child sets, current protection epochs,
source spelling and official projections. It retains the original before-native
start and closes subtree metadata handles before the public SDK move. Recovery
uses the same proof and does not infer movement from Windows path existence.

After successful public reconciliation, a narrowly scoped target metadata reader
permits checks of only the original sealed target members while normal routing
still names the source. Independent native Label evidence, root facts and all
descendant projections precede the existing atomic product transaction. That
transaction transfers names, all positions and the Label together and releases
both durable fences. Current catalog routing is refreshed afterwards, including
when a return was lost after completion. Historical replay never restores an old
Label or authorizes a new native operation.

The new native composite has fourteen independent thirty-second executions:
Active and Disabled roots at success, start-write, after-native,
after-observation, after-projection, final atomic-write and lost-client-return
boundaries. It reopens three catalog/SDK owners, uses the production root policy
for actual movement/recovery, verifies an earlier child move, all private bytes,
strict ordinary deletion refusal, a later case-only Label and immutable original
history. Original preparation and generic/native cases retain their deadlines.

The public sequence is `root prepare-rename <root-id> <label>` followed by
`root execute-rename <original-operation-id>`. Both use the typed current-user
Control pipe. Preparation drains accepted root work before capturing read-only
SDK proof. Execution drains outside instance/library serialization, seals the
current protected subtree, executes that original move, and requires its atomic
Label and complete subtree receipt. A fresh current-role audit under retained
native guards precedes active-root readmission. Disabled roots can change their
local Label and remain closed to source work.

The response distinguishes the immutable original receipt from today's directory
name, current audit and admission. Retrying an older completed operation after a
later Label returns the old receipt with the current name; it cannot revert the
root. Journal acceptance belongs to the ordinary pump after the command releases
its root work. The command does not wait for its own journal ACK or call a Worker.

The additional public-runtime native fixture has four sixty-second executions:
Active/Disabled crossed with normal/case-only first labels. It disposes the setup
owner before starting a fresh runtime role, then uses the public prepare/execute
methods, checks actual work draining, four members and private bytes, refuses
ordinary deletion, and retries an earlier receipt after a later Label. It does
not create a Label intent before changing roles and does not prove independent
Host process restart, signed Worker integration, or interrupted pre-native role
replacement. Those recovery and concurrency requirements remain open. Existing
native cutpoint deadlines and assertions are retained. Clean native/installed CI
evidence is required; builds, managed pipe tests and discovery alone cannot
establish native acceptance.
