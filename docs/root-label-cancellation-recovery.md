# Born-root Label cancellation recovery

A configured first-level root can be a protected birth below the physical sync
anchor. It has no original permission-tree capture. After a Host restart, anchor
role rotation can update its inherited ACE principals while a prepared Label
correctly keeps that root closed. Its retained birth protection then describes
an earlier descriptor. The presence of today's role in the actual ACL does not
authorize adopting that descriptor.

For an unsealed original Label with no pending initializer, cancellation admits
a version 5 selected-root current-inventory initializer in one catalog
transaction. Its immutable purpose identifies the original Label operation,
complete public-proof digest, registered born-root member and physical anchor.
Admission validates the original still-prepared public Label, unchanged source
mapping, exact native binding and owner, complete bounded registered tree, and
absence of native move ownership. Repeated attempts retain the first initializer
and fingerprint. The general initializer API cannot manufacture this admission.
Version 1 through 4 payloads retain their existing JSON shape and behavior.

This admission records work to recover. It supplies no native permission,
cancellation receipt, backend authority or readiness. Existing born recovery
settles parents before children and retains immutable action successors. Native
guards require the original binding, owner, public identity and direct parent.
The parent must match its retained verified descriptor before and after the
work. A child's actual descriptor must match retained owned protection, an
owned recovery target, or the exact inherited target computed from that verified
parent. A principal change alone is insufficient. The first birth observation
and original Label proof remain unchanged.

Startup preserves this purpose while the original Label is prepared. Only its
original cancellation path settles that work and obtains the public NotMoved
result under the complete source guards. Atomic cancellation retains the exact
initializer fingerprint. The Host then resumes this same dedicated initializer,
performs a fresh current-role native audit and releases its initialization fence
on completion. Active roots can be admitted after that audit; disabled roots
remain offline. A crash after atomic cancellation can resume the same retained
initializer at startup.

Older pending initializers keep their existing explicit recovery requirement.
They are not automatically completed by cancellation. Historical cancellation
replay preserves its original receipt and later committed names; it still
requires fresh current-tree recovery and audit before current admission.

The native regression starts with an empty original anchor, creates a real
inherited remote root and controlled descendants, imports resident bytes, then
prepares Label before fully disposing the first role. Under a new runtime role
it verifies the inherited principal transition and closed startup admission,
uses public cancellation, checks the exact dedicated initializer's completion,
and preserves first observations, stable members, later Label and resident bytes.
It runs enabled and disabled variants in disposable Windows verification.
Private catalog tests separately cover persistence, immutable correlation,
legacy owners, chronology, generic-route and sealed-ownership refusals, rehashed
purpose substitution, and completion only after the exact atomic cancellation.
