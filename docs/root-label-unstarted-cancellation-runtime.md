# Cancelling an unstarted protected root Label

`root cancel-rename OPERATION_ID` uses the versioned typed Host command
`root.cancelRename`. Clients receive the original cancelled operation, its
timestamp, today's directory name and separately inspected current admission;
they receive no native proof, ACL or Host database access.

The Host queues behind earlier overlapping recovery owners and drains root work
outside instance/library serialization. Cancellation leaves admission closed;
only an independently successful fresh audit can reopen it. Under the
shared namespace actor, the original current-user owner retains metadata-only
anchor and complete original source-tree handles. It authenticates the original
CfSharp proof through the public `ReconcileMoveAsync` result and accepts only
`NotMoved` with no native/projection/rescan flags, updated entries or error.
Complete membership, current positions, public identities, native bindings,
owners, types, descriptors, aliases and exact child sets are checked again
before the atomic cancellation transaction. Sealed moves retain their schema91
cancellation owner. Schema92 separately records preparations that acquired no
namespace move, without creating a move, reservation or predecessor claim.
No native move, source
request, permission write or journal ACK belongs to that cancellation scope.

An actual durable before-native start refuses cancellation even when the object
still appears at source. Observed/projected/completed originals also refuse.
The original role is never adopted after restart; old descriptors are inspected
read-only as the normal owner. Both current-role and older-role unsealed
preparations use the separate unsealed cancellation path. The complete inventory
is checked against original membership, retained identity, position and
protection provenance. Any move ownership or uncertain actual state refuses
this path. An independently recovered current anchor can have a newer protection
epoch than the untouched original descendants.

After historical inspection guards expire, a separate current-tree recovery
operation and fresh retained audit may admit an active root. Disabled roots
remain closed. Another current fence returns the immutable cancellation with
`currentTreeAudited=false` and `namespaceReady=false`, without releasing that
owner. Retrying an earlier cancellation keeps its original ID/timestamp and
today's later Label. Logging or cancellation history is never current authority.

The clean native producer retains four enabled/disabled by same/new-role
cancellation cases and two new-role start-written-but-unmoved refusal cases.
Each keeps its original 60-second bound, complete four-member graph and resident
bytes. It also refuses a completed cancellation and replays after a later Label.
An additional mandatory method selects two enabled/disabled preparations that
cross role disposal with only their original public proof. It requires actual
public `NotMoved`, the complete four-member graph, immutable replay and later
Label preservation, while asserting that no namespace move or snapshot was
manufactured. Both additional cases retain individual 60-second deadlines.
This fixture uses separate runtime roles, not an independent full Host process
or signed Worker. Actual native results, full fault/rollback cuts, concurrency
and independent signed Host restart acceptance remain pending until verified.

The preparation diagnostic also records a closed stage: root work drain,
instance/library serialization, original ownership, current-tree audit or public
proof/preparation. Nested stages retain the deepest failure and the same original
exception. This locates an otherwise unknown failure without recording its
message or weakening any guard; the prior signed `Unknown/80131509` remains an
unresolved historical negative. A later source-bound signed reproduction at
f6766a7 identifies `RootWorkDrain` / `PendingTransition` / `80131509`, before
instance/library serialization or CfSharp proof acquisition. Queued public
recovery addresses that immediate ownership collision; only the complete new
signed lifecycle can establish end-to-end acceptance.
