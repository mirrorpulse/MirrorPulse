# Observed root Label recovery under a new Host role

The internal observed-root recovery entry can finish only a root that has already
moved under its original public SDK proof and original before-native start. It
runs as the captured current-user owner, reads the exact original descriptors and
bindings of the complete sealed target tree, and reuses the original independent
native Label observation and atomic whole-subtree settlement. It never issues a
native move, writes a DACL, reads a source or acknowledges a journal.

A new execution role does not adopt the original permission epoch. Startup must
finish this original metadata settlement before rotating any member's permissions;
normal owned current-tree recovery may then establish the new role at the committed
positions. Product completion alone grants no current namespace readiness. Original
completed replay refreshes only today's catalog mapping.

The new native composite contains eight independent thirty-second executions:
Active and Disabled roots at unstarted, after-native, after-observation and
after-projection boundaries. Three real catalog/SDK owners dispose the old SDK
before disposing its execution token and creating a genuinely different role. The
recovery token must lack the old role. The fixture verifies original proof/facts,
all native bindings, complete bytes, old descriptor epochs, strict ordinary delete
refusal and safe unstarted refusal without inventing a start. Production root policy
is used for actual movement and recovery; there is no blanket Allow override.

Before-native new-role readmission, partial SDK projection faults, later current
tree role rotation, public Host/Control/CLI wiring and durable original root journal
ownership remain separate S06 requirements. This internal entry and local discovery
are not a claim of full Host process-restart or native acceptance.
