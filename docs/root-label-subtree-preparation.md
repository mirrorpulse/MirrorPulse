# Original protected root Label subtree preparation

The internal member-move coordinator can seal the complete currently protected
subtree of an already prepared root Label operation. It reuses the same original
operation ID and opaque public CfSharp proof; it never captures a replacement
proof or moves the native root during preparation.

The original SDK binding selects the current root member through the product's
indexed full-binding lookup. The current first-level source, physical sync-root
anchor, owner, namespace role, protection epochs, public identities, official
positions and complete local tree must agree. Unregistered objects, missing
members, an occupied target, an altered source spelling or another anchor refuse
admission. The existing catalog transaction seals all members and keeps both
original root Label and controlled-member responsibilities pending.

Before new admission the public SDK must authenticate that original preparation
as NotMoved, without native movement, projection commitment or a rescan request.
Public decoding alone cannot establish the original store relationship. A later
native executor must independently revalidate the original proof again.

Replay returns the same admitted operation. A completed historical replay requires
its original whole-subtree receipt and cannot move or revert a later Label. Missing
admission after native movement is not reconstructed retrospectively. The generic
child-move and same-root checks remain unchanged.

The caller retains current root and instance admission. Disabled lifecycle is
independent of a successful local namespace audit; local preparation must not enable
Worker dispatch. A closed root needs its required actual recovery/audit. New
preparation must not borrow the historical pending-operation entry to bypass those
requirements.

This is a preparation prerequisite. It does not activate protected native root
execution in the current public Host/Control/CLI or generic move entry. Controlled
movement, target metadata inspection, independent native and public results,
atomic subtree/Label settlement, routing refresh, original journal ownership/ACK
and startup recovery remain separate required S06 work. Native component fixtures
do not represent full signed Host acceptance or close P078.
